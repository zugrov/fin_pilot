# Форматы импорта

Поддержаны только эти контракты. Неизвестный заголовок, кодировка или версия отклоняются кодом `unsupported_format`. Универсальное чтение отчётов 1С не заявляется. `revenue.csv` — формат сервиса, не выгрузка 1С. Fixtures синтетические и не загружаются в рабочие фирмы: `backend/tests/fixtures/imports/`.

## cash_transactions.csv и такой же лист XLSX

Колонки строго в этом порядке:

`external_id,wallet_code,business_date,direction,amount,currency,counterparty_inn,counterparty_name,description,document_number,category_code,direction_code`

- Дата `YYYY-MM-DD`.
- Сумма больше нуля, до копейки, разделитель точка. Число Excel с плавающей точкой отклоняется.
- `direction`: `in` или `out`. Знак суммы направление не задаёт.
- Валюта только `RUB`.
- `wallet_code` — код кошелька фирмы.
- Формула в сумме без значения отклоняется.
- Кодировка профиля: `utf-8`, `utf-8-sig` или `cp1251`.

## ClientBankExchange 1.03

Первая строка `1CClientBankExchange`, поле `ВерсияФормата=1.03`. Другая версия отклоняется.

Документ между `СекцияДокумент` и `КонецДокумента`. `ДатаСписано` — выплата, `ДатаПоступило` — поступление. Оба поля или ни одного — ошибка строки. `Номер` — внешний идентификатор, `Сумма` — сумма, `НазначениеПлатежа` — описание. Кошелёк берётся из привязки источника, не из файла.

`ДатаКонца` в шапке, до первой секции, задаёт покрытие в формате `ДД.ММ.ГГГГ`. Дата получения письма покрытие не задаёт. Файл без документов и с `ДатаКонца` подтверждает покрытие и операций не создаёт. Файл без документов и без `ДатаКонца` отклоняется. Более поздняя выписка не уступает место более ранней.

Почтовое вложение денег — только этот контракт. Другой отчёт 1С отклоняется кодом `unsupported_format`. Фирма берётся из источника, не из имени файла. Письмо само операции не проводит.

## revenue.csv

Колонки строго в этом порядке:

`external_id,recognition_date,document_number,counterparty_inn,amount_ex_vat,vat_amount,amount_inc_vat,entry_type,direction_code`

- Дата признания `YYYY-MM-DD`.
- `entry_type`: `sale` или `return`. Суммы положительные, знак задаёт тип.
- При базе `net` три суммы обязательны и сходятся до копейки. НДС может быть нулём.
- Контракт выбирается по полю источника `dataset=revenue`, не по имени файла.
- Файл продаж на денежный источник и денежный файл на источник продаж отклоняются.
- Пустой ИНН допустим. Неизвестный `direction_code` — ошибка строки.

## planned_cash.csv

Колонки строго в этом порядке:

`external_id,direction,amount,currency,due_date,expected_date,category_code,counterparty_inn,confidence,priority,wallet_code`

- Даты `YYYY-MM-DD`. Сумма больше нуля, до копейки. Валюта только `RUB`.
- `direction`: `in` или `out`. `confidence`: `confirmed`, `expected`, `tentative`. `priority`: `critical`, `high`, `normal`, `low`.
- Контракт выбирается по `dataset=plan`, не по имени файла. Источник плана только CSV.
- Пустые `wallet_code`, `category_code` и ИНН допустимы. Неизвестный код — ошибка строки.
- Commit не создаёт денежную операцию. Ревизия не удаляет `PaymentMatch` и не опускает сумму ниже уже оплаченной части.
- Это формат сервиса, не шаблон 1С. Синтетический файл не загружается в рабочие фирмы сам.

## budget.csv

Колонки строго в этом порядке:

`year,month,basis,metric_type,category_code,direction_code,amount,distribution_method`

- `basis`: `cash` или `revenue`. `metric_type`: `cash_in`, `cash_out` или `revenue`. Денежная база не содержит `revenue`, база выручки не содержит денежных метрик.
- `distribution_method` только `calendar_days`. Сумма не меньше нуля, до копейки.
- Контракт выбирается по `dataset=budget`, не по имени файла. Источник бюджета только CSV.
- Пустые `category_code` и `direction_code` допустимы. Неизвестный код — ошибка строки.
- Commit создаёт или дополняет черновик и дневные доли. Утверждения, денежной операции и планового события commit не делает.
- Это формат сервиса, не шаблон 1С. Синтетический файл не загружается в рабочие фирмы сам.

## Дедупликация

Повтор байтов файла не создаёт операций. Тот же `external_id` и тот же payload — повтор. Изменённый payload — ревизия существующей операции. Одинаковые дата, сумма и описание с разными `external_id` одного источника — две операции. Единственное совпадение из другого источника связывает вторую source identity с той же операцией. Несколько совпадений остаются в review и не проводятся.
