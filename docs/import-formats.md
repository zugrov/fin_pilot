# Форматы импорта

**В продукте поддержаны** только контракты ниже (кроме отдельно помеченных). Неизвестный заголовок, кодировка или версия отклоняются кодом `unsupported_format`. Универсальное чтение отчётов 1С не заявляется. `revenue.csv` — формат сервиса, не выгрузка 1С. Fixtures синтетические и не загружаются в рабочие фирмы: `backend/tests/fixtures/imports/`.

**Согласовано с владельцем; реализовано и проверено локально (2026-10-17), не выложено и не принято:** `balances.csv` (FA-R01.2, пакет 2). Миграция `20261017_0010` (расширение CHECK `dataset` значением `balances`) согласована; применена только на `finpilot_test@127.0.0.1:5432` через pytest. Staging/deploy и приёмка пакета 2 — отдельное решение.

## cash_transactions.csv и такой же лист XLSX

Колонки строго в этом порядке:

`external_id,wallet_code,business_date,direction,amount,currency,counterparty_inn,counterparty_name,description,document_number,category_code,direction_code`

- Дата `YYYY-MM-DD`.
- Сумма больше нуля, до копейки, разделитель точка. Число Excel с плавающей точкой отклоняется.
- `direction`: `in` или `out`. Знак суммы направление не задаёт.
- Валюта только `RUB`.
- `wallet_code` — код кошелька фирмы.
- Формула в сумме без значения отклоняется.
- Кодировка профиля: `utf-8`, `utf-8-sig` или `cp1251`.

### Опциональные колонки ревизии (cash CSV/XLSX, revenue/plan/budget CSV)

После обязательных колонок контракта, **в этом порядке**, можно добавить:

`source_entity_id,source_revision,operation`

- `source_entity_id` — alias для `external_id`; если оба заданы, после нормализации (trim) значения должны совпадать, иначе ошибка строки.
- `source_revision` — целое `0 … 2^63-1`, только десятичные цифры без знака, дробей и экспоненты.
- `operation`: `upsert` (по умолчанию) или `unpost`. Любое другое значение, включая `delete`, отклоняется.
- `unpost` требует стабильный ID; суммы и даты для такой строки не обязательны. Строка уходит в review, commit не меняет финансы.
- ClientBank **не** добавляет эти колонки; commit всё равно не позволит unversioned overwrite уже versioned identity.

## ClientBankExchange 1.03

Первая строка `1CClientBankExchange`, поле `ВерсияФормата=1.03`. Другая версия отклоняется.

Документ между `СекцияДокумент` и `КонецДокумента`. `ДатаСписано` — выплата, `ДатаПоступило` — поступление. Оба поля или ни одного — ошибка строки. `Номер` — внешний идентификатор, `Сумма` — сумма, `НазначениеПлатежа` — описание. Кошелёк берётся из привязки источника, не из файла.

`ДатаКонца` в шапке, до первой секции, задаёт покрытие в формате `ДД.ММ.ГГГГ`. Дата получения письма покрытие не задаёт. Файл без документов и с `ДатаКонца` подтверждает покрытие и операций не создаёт. Файл без документов и без `ДатаКонца` отклоняется. Более поздняя выписка не уступает место более ранней.

Почтовое вложение денег — только этот контракт. Другой отчёт 1С отклоняется кодом `unsupported_format`. Фирма берётся из источника, не из имени файла. Письмо само операции не проводит.

## revenue.csv

Колонки строго в этом порядке:

`external_id,recognition_date,document_number,counterparty_inn,amount_ex_vat,vat_amount,amount_inc_vat,entry_type,direction_code`

- Дата признания `YYYY-MM-DD`.
- `entry_type`: `sale` или `return`. Суммы положительные, знак задаёт тип.
- При базе `net` три суммы обязательны и сходятся до копейки. НДС может быть нулём.
- Контракт выбирается по полю источника `dataset=revenue`, не по имени файла.
- Файл продаж на денежный источник и денежный файл на источник продаж отклоняются.
- Пустой ИНН допустим. Неизвестный `direction_code` — ошибка строки.
- Опциональный суффикс ревизии — см. cash выше.

## planned_cash.csv

Колонки строго в этом порядке:

`external_id,direction,amount,currency,due_date,expected_date,category_code,counterparty_inn,confidence,priority,wallet_code`

- Даты `YYYY-MM-DD`. Сумма больше нуля, до копейки. Валюта только `RUB`.
- `direction`: `in` или `out`. `confidence`: `confirmed`, `expected`, `tentative`. `priority`: `critical`, `high`, `normal`, `low`.
- Контракт выбирается по `dataset=plan`, не по имени файла. Источник плана только CSV.
- Пустые `wallet_code`, `category_code` и ИНН допустимы. Неизвестный код — ошибка строки.
- Commit не создаёт денежную операцию. Ревизия не удаляет `PaymentMatch` и не опускает сумму ниже уже оплаченной части.
- Это формат сервиса, не шаблон 1С. Синтетический файл не загружается в рабочие фирмы сам.
- Опциональный суффикс ревизии — см. cash выше.

## budget.csv

Колонки строго в этом порядке:

`year,month,basis,metric_type,category_code,direction_code,amount,distribution_method`

- `basis`: `cash` или `revenue`. `metric_type`: `cash_in`, `cash_out` или `revenue`. Денежная база не содержит `revenue`, база выручки не содержит денежных метрик.
- `distribution_method` только `calendar_days`. Сумма не меньше нуля, до копейки.
- Контракт выбирается по `dataset=budget`, не по имени файла. Источник бюджета только CSV.
- Пустые `category_code` и `direction_code` допустимы. Неизвестный код — ошибка строки.
- Commit создаёт или дополняет черновик и дневные доли. Утверждения, денежной операции и планового события commit не делает.
- Это формат сервиса, не шаблон 1С. Синтетический файл не загружается в рабочие фирмы сам.
- Опциональный суффикс ревизии — см. cash выше; `source_entity_id` может задать ключ строки вместо синтетического `{year:month:…}`.

## balances.csv (контракт согласован; локально verified, не принято)

**Локальная проверка 2026-10-17:** 22 сценария в `test_balances_import.py` + 6 migration + 2 rollback-compat; backend pytest **232 passed / 1 failed**; **backup/restore локально не подтверждён** (pg_dump `127.0.0.1:5433`). **Staging:** пакет 2 не выложен, `0010` не применена — импорт balances на staging недоступен.

Колонки строго в этом порядке:

`wallet_code,as_of,balance,currency`

- Контракт выбирается по полю источника `dataset=balances`, не по имени файла. Источник только CSV (`type=file`, `format=csv`).
- **`as_of`:** только календарная дата `YYYY-MM-DD`. Момент opening = **начало этого дня в timezone фирмы** (поле `companies.timezone`), в API хранится как timezone-aware `effective_at`.
- **`balance`:** сумма **начального остатка (opening anchor)**, не вычисленный текущий баланс после операций. **`0.00` допустим.** Сумма до копеек, разделитель точка; отрицательные значения — ошибка строки.
- **`wallet_code`:** код **существующего** счёта выбранной фирмы; создание счёта из файла не предусмотрено.
- **`currency`:** должна **совпадать** с валютой счёта; иначе ошибка строки.
- Повтор **`wallet_code` в одном файле** блокирует проведение **всего batch** (commit недоступен до исправления файла).
- **Preview** не изменяет opening, audit и прочие финансовые данные. По строке показывается намерение **create** / **replace** / **unchanged** и снимок **до/после** (active opening, если был).
- **Commit** — **строго all-or-nothing:** при любой ошибке строки, stale preview или сбое в середине транзакции opening не меняется.
- **Stale preview:** если active opening, `wallet_code`, валюта счёта или timezone фирмы изменились после preview, commit → **409** `stale_preview`; нужны **POST refresh-preview** (CSRF) и новый **Preview-Token**. Повтор upload того же файла (dedup по hash) **не** обновляет snapshot.
- **Preview-Token:** выдаётся в preview/refresh; commit balances требует заголовок `Preview-Token`, совпадающий с актуальным snapshot. После refresh старый token **не** проводит commit.
- Batch в статусе **completed**: повтор commit **не** применяет opening повторно (replay payload).
- Commit **не** запускает пересчёт alerts, внешние отправки и прочие побочные jobs вне существующего audit/opening path.
- Кодировка: `utf-8`, `utf-8-sig` или `cp1251`.

## Дедупликация

Повтор байтов файла не создаёт операций. Тот же `external_id` и тот же payload — повтор. Изменённый payload — ревизия существующей операции. Одинаковые дата, сумма и описание с разными `external_id` одного источника — две операции. Единственное совпадение из другого источника связывает вторую source identity с той же операцией. Несколько совпадений остаются в review и не проводятся.
