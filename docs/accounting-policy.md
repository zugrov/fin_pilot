# Учётная политика и финансовые инварианты

Версия документа: 1.0. Источник: ТЗ v2.0, §8. На этапах 0–2 политика фиксируется. Расчётное ядро реализуется на этапах 3–7 и обязано ей соответствовать.

Это управленческая надстройка. Она не заменяет бухгалтерию, не сдаёт отчётность, не правит документы в 1С и не исполняет банковские платежи клиента.

## Деньги и отсутствие данных

- Сумма операции положительная. Знак берётся из направления `in`/`out`.
- Нет данных: значение `unavailable` и quality flag. Ноль не подставляется.
- Ноль допустим только когда покрытие источника полное и событий действительно не было.
- Поступления не равны выручке. Чистый денежный поток (`cash-in − cash-out`) не называется прибылью. Accrual P&L вне beta.

## Балансы и ликвидность

`Balance(wallet, t) = anchor + posted incoming − posted outgoing` от `effective_at` до `t`.

- В расчётах участвуют только `posted`. `draft` и `void` не двигают остаток.
- Операции раньше anchor не влияют на последующий баланс.
- Нет anchor: баланс `unavailable`, не 0. Флаг `missing_opening_balance`.
- Только `business_date` означает конец дня. Внутридневная оценка помечается отдельно.
- Общий cash: все кошельки управленческого периметра.
- Available cash: только spendable. Restricted deposit не доступен до `available_from`.
- Headroom = available − reserve. Резерв не вычитается второй раз.
- Снимок источника сверяет остаток и не подменяет его молча. Расхождение закрывается отдельной технической posted-операцией.

## ДДС, переводы, группа

Категории движения: operating, investing, financing, technical.

- Внешний posted-поток меняет cash. Займы и средства собственника — financing, не выручка.
- Перевод между своими кошельками меняет остатки кошельков и не входит во внешний оборот фирмы.
- Межфирменный перевод виден в каждой фирме. В группе обе подтверждённые ноги исключаются из внешнего оборота только если обе фирмы внутри scope. Нет пары или одна фирма вне scope: не исключать.
- Положительный cash группы не означает, что деньги юрлиц взаимозаменяемы. Кассовый разрыв фирмы показывается даже при положительном итоге группы.
- Перевод в restricted deposit внутри фирмы не внешний оборот, но меняет available cash.
- Возврат покупателю: денежный эффект по дате выплаты, уменьшение выручки по `recognition_date`.
- Несопоставленные категории остаются отдельной группой и не исчезают.

## Выручка

`Revenue = posted sales ex_vat − returns ex_vat` по `recognition_date`.

- Нет источника продаж: `unavailable`, не 0 и не cash-in. Флаг `missing_revenue_source`.
- Полное покрытие и ноль продаж: 0 допустим.
- Неизвестная база НДС: подпись «сумма продаж по данным источника», флаг `vat_basis_unknown`. Это не net revenue.
- Сумма выручки группы до исключения внутригрупповых продаж так и подписывается. Полноценной консолидации в beta нет.
- Аванс, займ, вклад собственника и внутренний перевод сами по себе продажу не создают.
- `RevenueCashMatch` справочный и не признаёт выручку.

## План, бюджет, обязательства

- Остаток события = сумма − сопоставления с posted. Неотрицательный. Валюта, фирма и направление совпадают. Сумма распределений не больше суммы операции.
- Оплаченная часть уже в факте. В прогноз попадает только остаток.
- Void связанного факта возвращает остаток после пересчёта.
- Неоднозначное автосопоставление — предложение, его подтверждает человек.
- Бюджет не создаёт событие прогноза. Один платёж не считается трижды из бюджета, события и обязательства.
- `Obligation` порождает один residual forecast event, не второй дубль.
- Cash-бюджет сравнивается с денежным фактом, revenue-бюджет с `RevenueEntry`. Базы не взаимозаменяемы.
- Нет утверждённого бюджета: отклонение `unavailable`, алерт отклонения не создаётся.
- План 0 и факт 0: процент 0. План 0 и факт не 0: процент null, статус «вне бюджета».

## Прогноз

Горизонт 91 календарный день. Конец дня, не обещание внутри дня.

- Base: confirmed и expected притоки, плановые выплаты. Tentative притоки исключены.
- Conservative: expected приток задерживается на 7 дней и берётся как 80% остатка. Confirmed без haircut. Расходы не уменьшаются.
- Optimistic: base плюс явные tentative. Выдуманного роста нет.
- Автоэкстраполяция выручки в beta выключена.
- Неполный вход: прогноз preliminary, формулировка «рисков нет» запрещена.
- Просроченные payables попадают на ближайший день прогноза. Просроченные receivables не становятся confirmed без нового ожидания.

## Качество

Флаги: `missing_opening_balance`, `stale_cash_source`, `partial_period`, `missing_revenue_source`, `vat_basis_unknown`, `unclassified_operations`, `reconciliation_difference`, `ambiguous_duplicates`, `missing_budget`, `stale_forecast`.

Плохое качество не скрывает доказанный риск и запрещает уверенный all-clear. Частичная группа подписывается явно.
