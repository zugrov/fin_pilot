# Шаблоны пилота

В этом каталоге лежат только пустые заголовки форматов, которые импорт уже принимает. Строк данных нет. Неизвестный заголовок приложение отклоняет как `unsupported_format`.

Контракт колонок: `docs/import-formats.md`.

| Файл | Что делает commit |
|---|---|
| `cash.csv` | Денежные операции `posted`. Дата `YYYY-MM-DD`, сумма больше нуля с точкой, валюта `RUB`, направление `in` или `out` |
| `revenue.csv` | Продажи и возвраты. `entry_type`: `sale` или `return`. Три суммы сходятся до копейки |
| `planned_cash.csv` | План. Денежную операцию не создаёт |
| `budget.csv` | Черновик бюджета. Метод только `calendar_days`. Операции не создаёт и бюджет не утверждает |

Выписка банка — отдельный текст `1CClientBankExchange` версии `1.03`, не CSV из этого каталога. Почтовое вложение денег принимается только в этом формате. Кошелёк берётся из источника.

Повтор тех же байтов или того же `external_id` с тем же payload операций не создаёт. Изменённый payload ревизует строку. Сумма ревизии плана не опускается ниже уже сопоставленной части.

## Счета и кассы

Файлового импорта нет. Счёт создаётся `POST /api/v1/companies/{company_id}/wallets`.

Поля тела:

- `name` — название
- `type` — `bank`, `cash`, `business_owner_card`, `deposit` или `other`
- `availability_type` — `spendable` или `restricted`
- `available_from` — момент ISO с часовым поясом, необязательно
- `minimum_reserve` — строка суммы, по умолчанию `0.00`
- `masked_identifier` — необязательно
- `code` — код кошелька. Для импорта денег код обязателен: колонка `wallet_code` ищет этот код

Суммы в API передаются строками.

## Начальный остаток

Файлового импорта нет. Один активный остаток на кошелёк задаётся `POST /api/v1/wallets/{wallet_id}/opening-balance`.

Поля тела:

- `effective_at` — момент ISO с часовым поясом
- `amount` — строка суммы, ноль допустим

Повторный вызов заменяет прежний активный остаток. Отсутствие остатка в отчёте — quality flag `missing_opening_balance`, не ноль.

## Сопоставление оплаты с планом

Файлового импорта нет. Частичная оплата связывается `POST /api/v1/payment-matches`.

Поля тела:

- `company_id`
- `event_id` — плановое событие
- `cash_transaction_id` — уже проведённая денежная операция
- `amount` — строка суммы сопоставления

## Контрольные итоги

Импортёр контрольные итоги не читает. Отдельного файла для них нет: такой файл выглядел бы как поддержанный формат, хотя приложение его не примет.

Итог сверяется снаружи: сумма и число строк исходной выгрузки сравниваются с preview и с проведёнными строками после commit. Расхождение не подменяется нулём и не проводится молча.
