# Готовность к live-запуску

Этот список не блокирует test/mock-разработку. Пока пункт не закрыт, соответствующее боевое действие выключено флагом и не подменяется успехом.

## Продавец и оплата

- [ ] Организационно-правовая форма продавца, наименование, ИНН, система налогообложения.
- [ ] Применимость чека: нужен ли чек, предмет расчёта, способ расчёта, аванс или полный расчёт.
- [ ] Ставка НДС из документов продавца. В коде ставки по умолчанию нет.
- [ ] Версия оферты и текст, который увидит клиент. Техническая политика биллинга офертой не является.
- [ ] `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, боевой `YOOKASSA_RETURN_URL`.
- [ ] Актуальный список IP уведомлений ЮKassa для allowlist.
- [ ] `RECEIPT_MODE` согласован. Пока он пуст, live checkout закрыт.
- [ ] `SEND_LIVE_PAYMENTS` остаётся `false` до явного разрешения заказчика.
- [ ] Возвраты: кто подтверждает, какие основания. До разрешения staff-refund выключен.
- [ ] Webhook в кабинете ЮKassa регистрируется отдельно, не из Compose и не из этого репозитория без approval.

## Почта и Telegram

- [ ] Провайдер писем, домен, SPF/DKIM. `SEND_REAL_EMAIL` остаётся `false`.
- [ ] `BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`. `SEND_EXTERNAL_MESSAGES` остаётся `false`.
- [ ] Боевой webhook Telegram регистрируется только после разрешения. В разработке long polling, не одновременно с webhook.

## 1С и пилотные файлы

- [ ] Реальный шаблон выгрузки 1С, согласованный с разработчиком 1С.
- [ ] Пилотные файлы заказчика для сверки двух фирм. В репозиторий не класть персональные данные.
- [ ] Список реально поддержанных конфигураций. Неизвестный формат отклоняется явно, универсальное чтение отчётов 1С не заявляется. Синтетические CSV, XLSX и ClientBankExchange 1.03 этот пункт не закрывают.
- [ ] Выделенный почтовый ящик, фильтры отправителя и папки, ключ шифрования учётных данных IMAP.

## Инфраструктура

- [ ] VPS, домен, `PUBLIC_BASE_URL`, TLS.
- [ ] Docker/Compose и Linux prefork Celery не проверены. Локально worker и beat подключаются к Redis. На macOS пул prefork падает в трейсере Celery до тела задачи; пул solo выполняет `billing.process_inbox` и `mail.dispatch_outbox`.
- [ ] Боевые `DATABASE_URL`, `REDIS_URL`, `SESSION_SECRET`, `SECRET_ENCRYPTION_KEY` вне git.
- [ ] Роли БД: миграции отдельно от приложения, минимум прав.
- [ ] Проверенное восстановление backup. Цели RPO 24ч и RTO 4ч подтверждаются процедурой, а не обещанием.
- [ ] Решение по контуру размещения данных и передаче данных в Telegram до пилота.

Закрытие пункта отмечается датой и ссылкой на решение, а не снятием флага «на всякий случай».
