# REL1 · записка по `decisions_needed` (STATE.json)

**Дата:** 2026-10-27. **Режим:** подготовка, без кода и без VPS.  
**Источники:** `docs/roadmap/STATE.json` → `decisions_needed`, `docs/roadmap/DECISIONS.md` (D1, D5, D6), `MASTER_PLAN.md` (FA-R03…R07).

Цель: для каждого открытого пункта — суть, варианты, влияние на roadmap, рекомендуемый **default** (до ответа владельца), что блокирует, **минимум для старта FA-R03.1**.

Легенда блокировок:

- **Пилот (FA-R10)** — первый реальный файловый/почтовый контур с данными заказчика.
- **FA-R03.1** — «Матрица образцов»: обезличенные файлы, контрольные итоги, описание конфигурации 1С **без угадывания**.

## 1. `first_1c_configuration_platform_and_hosting`

**Суть (D1):** какая конфигурация 1С, версия платформы и где живёт база (облако/сервер заказчика/VPS) — **неизвестно**. БП 3.0 не выбирается по умолчанию.

| Вариант | Описание |
| --- | --- |
| **A** | Уточнить у заказчика: конфигурация + релиз платформы + способ выгрузки (файл/HTTP/COM). |
| **B** | Зафиксировать **учебный** профиль (например «услуги без склада») на **демо-базе** 1С — только для синтетики/FA-R03 матрицы, **не** как решение для пилота. |
| **C** | Отложить 1С; FA-R03.1 начать с **ClientBank + XLSX/CSV** без 1С-выгрузок. |

**Влияние на этапы:**

| Этап | Влияние |
| --- | --- |
| FA-R03 | Парсеры и матрица образцов **привязаны** к полям конкретной конфигурации. |
| FA-R04–R05 | Почта/Excel — **частично** независимы от 1С. |
| FA-R06–R07 | Правила учёта и отчёты нуждаются в **согласовании** с планом счетов/аналитиками 1С. |
| FA-R11 | Прямой коннектор 1С **заблокирован** без A. |

**Default (до ответа владельца):** **C** для старта FA-R03.1 на **не-1С** файлах + параллельный сбор фактов **A** («нужен ответ владельца / образец выгрузки 1С»).

| Блокирует реальный пилот? | **Да** (канал 1С и сверка с ОСВ). |
| Блокирует FA-R03.1? | **Частично:** не блокирует **первую** матрицу на банк/CSV; **блокирует** строки матрицы «из 1С» без образца. |

**Минимум для FA-R03.1:** список **3–5** обезличенных файлов (ClientBank, продажи CSV, ОСВ **если есть**) + таблица «ожидаемые итоги»; строка 1С — **TBD** до образца.

## 2. `real_pilot_isolation_method_before_launch`

**Суть (D6):** как изолировать реального заказчика от синтетики ООО «Топ» — **не выбрано** (вариант A: второй слот на том же VPS vs B: отдельный контур).

| Вариант | Описание |
| --- | --- |
| **A** | Второй tenant/slot на **том же** staging-стеке (отдельная БД или tenant + жёсткий RBAC). |
| **B** | **Отдельный** VPS/namespace (DB, Redis, домен). |
| **C** | Прод-контур FA-R15 заранее; staging остаётся только synthetic (пилот **не** на staging). |

**Влияние:**

| Этап | Влияние |
| --- | --- |
| FA-R03–R09 | Разработка на synthetic — **без** выбора. |
| FA-R10 | **Прямо** задаёт организацию контура, backup, доступы. |
| FA-R06–R07 | Закрытый месяц пилота — нужна **изоляция** данных. |

**Default:** **C** для ближайших этапов (staging = synthetic + REL0 candidate); к FA-R10.1 вернуться к **A vs B**.

| Блокирует реальный пилот? | **Да.** |
| Блокирует FA-R03.1? | **Нет.** |

**Минимум для FA-R03.1:** зафиксировать в DECISIONS: «FA-R03.1 на **локальных/обезличенных** файлах, staging Top **не трогаем**» (уже согласовано D5).

## 3. `source_precedence_for_target_pnl_and_balance`

**Суть:** при расхождении источников (банк vs 1С ОСВ vs ручной ввод) — **что главное** для целевого ОПиУ, баланса, денег.

| Вариант | Описание |
| --- | --- |
| **A** | **Деньги:** банк/ClientBank первичны; бухгалтерия — сверка. |
| **B** | **Начисление:** 1С/бухгалтерия первична; банк — подтверждение оплаты. |
| **C** | **По сущности:** выручка из CRM/актов, деньги из банка, расходы — mixed с явной таблицей precedence (ADR). |

**Влияние:**

| Этап | Влияние |
| --- | --- |
| FA-R03.3 | Provenance и сверки **требуют** правила. |
| FA-R06.1–06.4 | Признание, закрытие периода. |
| FA-R07.2 | Контрольные равенства — **иначе** не формулируются. |

**Default:** **A** для текущего D3 (деньги, выручка, планы) + черновик ADR для **B** по начислению (FA-R06.1).

| Блокирует реальный пилот? | **Да** (сверка месяца с заказчиком). |
| Блокирует FA-R03.1? | **Нет** для **одноисточниковых** образцов; **да** для multi-source пакета без правила. |

**Минимум для FA-R03.1:** пометить каждый образец **одним** authoritative source; multi-source — **out of scope** до ADR.

## 4. `period_close_authority`

**Суть:** кто может закрыть период (роль, двухглазие, только бухгалтер).

| Вариант | Описание |
| --- | --- |
| **A** | Owner workspace закрывает период (простая модель). |
| **B** | Отдельная роль `period_close` / бухгалтер; owner не закрывает. |
| **C** | Закрытие только после checklist (полнота ingest, unresolved review = 0). |

**Влияние:**

| Этап | Влияние |
| --- | --- |
| FA-R06.4 | **Ядро** задачи. |
| FA-R07.4 | Закрытый пакет отчётов. |
| FA-R03 | Слабое (импорт не равен close). |

**Default:** **A** на staging/synthetic; **C** как целевое для FA-R06.4.

| Блокирует реальный пилот? | **Да** для «официального» закрытого месяца. |
| Блокирует FA-R03.1? | **Нет.** |

**Минимум для FA-R03.1:** none.

## 6. `ocr_llm_data_processing_boundary`

**Суть:** где обрабатываются PDF/сканы (FA-R05), уходят ли данные во внешний LLM/OCR, DPA, retention.

| Вариант | Описание |
| --- | --- |
| **A** | Только **on-prem / local** parser, без LLM. |
| **B** | Облачный OCR с **обезличиванием** и договором. |
| **C** | LLM для **извлечения полей** с human-in-the-loop; секреты запрещены в prompt. |

**Влияние:**

| Этап | Влияние |
| --- | --- |
| FA-R05 | **Блокирует** production OCR. |
| FA-R03 | Только если образцы — сканы без ручной разметки. |

**Default:** **A** до отдельного ADR; FA-R05.2 — два **ручных** профиля XLSX/PDF.

| Блокирует реальный пилот? | **Да**, если пилот = «сканы договоров в LLM». |
| Блокирует FA-R03.1? | **Нет** при структурированных XLSX/CSV/ClientBank. |

**Минимум для FA-R03.1:** явно **исключить** OCR/LLM из scope первой матрицы.
