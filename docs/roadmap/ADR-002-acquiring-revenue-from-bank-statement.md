# ADR-002 · Выручка эквайринга из банковской выписки (черновик)

**Статус:** черновик для обсуждения владельца и бухгалтера. **Без** кода и SQL.  
**Данные:** операционные файлы клиента только в `var/` (не в git).

---

## Контекст

Доля выручки через эквайринг существенна (порядка **70%** Кт **90.01** в пилотных месяцах по ОСВ). ОСВ (**57.03**, **90.01**) остаётся **эталоном учёта**. Выписка **ClientBank (S1)** даёт независимую линию: по строкам с распознаваемым шаблоном назначения извлекаются **валовая сумма**, **комиссия** и сверка с **зачислением** (поле суммы документа). Тексты назначений в git и в пользовательских отчётах **не храним**; в продукте — только **агрегаты и признаки качества**.

---

## Решение (черновик)

### 1. Источник и классификация

- **Источник:** строки выписки S1 (документы «поступило»), отфильтрованные по **согласованным шаблонам** (ключевые слова / regex на стороне импорта; список фиксируется в FA-R03 / FA-R06).
- **Признак в данных:** `revenue_source = acquiring_statement` (или аналог) + флаг **`derived_from_bank_statement`** для суммы выручки эквайринга, **если** итог месяца построен из выписки, а не только из ОСВ.

### 2. Самоконтроль по строке

Для каждой принятой строки эквайринга: **валовая − комиссия (из назначения) = зачисление (сумма документа)** с допуском **до 1,00** (округления в тексте назначения и в поле суммы). Строки вне допуска — в **нерзолв** или ручное подтверждение (без сохранения текста в открытом виде при необходимости — только хэш/тип шаблона).

### 3. Допуски сверки с ОСВ (предложение)

Эталон по транзиту: **Дт 57.03** (ОСВ за месяц).  
Комиссия эквайринга для сравнения с выпиской: **Дт 57.03 − сумма зачислений по эквайринговым строкам выписки за месяц** (эквивалент «**Дт 57.03 − Кт 57.03 (зачисление на 51)**» при нулевых сальдо **57.03**), **а не весь Дт 91.02**.

| Уровень | Предложение | Обоснование (пилотные данные локально) |
| --- | --- | --- |
| **Месяц, валовая** | ± **5,00** или ± **0,001%** от **Дт 57.03**, что **больше** | Отклонения **−1,20** и **−0,72** на два месяца |
| **Месяц, комиссия** | ± **10,00** или ± **0,05%** от эталона **(Дт 57.03 − зачисления)** | Отклонения **−7,04** и **−5,58** при эталоне **30 561,47** и **30 346,31** |
| **День, валовая vs Дт 57.03 по дням (S12)** | ± **1,00** на день, если нет статуса «перенос пачки» | На отмеченных днях расхождения **−0,79**, **−0,41**, **−0,71**, **−0,01** |

**«Считаем сверенной»:**

- **Месяц:** валовая и комиссия (по правилам выше) в допуске **и** нет строк в статусе «спор» / «неразобрано», **или** есть явное подтверждение бухгалтера на остаток.
- **По дням:** все дни с движением **57.03** в допуске **или** отмечены как **ожидаемый сдвиг** (см. ниже), без необъяснённых нулей.

Сдвиг дат между датой **поступления на 51** (выписка) и датой **Дт 57.03** (учёт по дням в **S12**) допускает расхождение по календарному дню при равенстве по месяцу; продукт может объединять сверку в «окно ±1 день» **только после** политики от владельца.

### 4. Возвраты и спорные платежи

- **Возвраты / сторно:** отдельная категория документов; не смешивать с валовой выручки за день без правила знака; при неоднозначности — `unavailable` по блоку или по дню.
- **Спорные:** не проходят самоконтроль **валовая − комиссия = зачисление**, или шаблон назначения неизвестен — не попадают в агрегат «по выписке» до разметки.

### 5. Влияние на контуры

- **Покрытие / ОПиУ:** выручка эквайринга из выписки — **вспомогательный** слой к ОСВ; при расхождении с **Дт 57.03** сверх допуска показывается **эталон ОСВ** и флаг качества; блок может быть `unavailable` по правилам D4/покрытия затрат.
- **Дебиторка:** эквайринг **не создаёт** дебиторскую задолженность **62.01**; связка **62/51** остаётся отдельным контуром (FA-R03.1). Путаница «поступление = выручка» исключена на уровне документации и UI.
- **Политика «поступление не равно выручке»:** зачисление на **51** по эквайрингу — **денежный поток**; **Дт 57.03** / **Кт 90.01** — **начисление**; пользователь видит оба слоя явно.
- **НДС:** представление сумм (с НДС / без) должно совпадать с **согласованной политикой** бухгалтера; выписка и ОСВ сверяются в **одной шкале** за период (вопрос к владельцу, зафиксировать в `var/`).

### 6. Сущности и миграции (описание, без SQL)

- Сущность **«сегмент выручки эквайринга за период»**: период, валовая, комиссия, зачисление, источник (`statement` / `ledger`), флаги полноты и допуска.
- Связь с **ImportBatch** / периодом закрытия — по существующим правилам FA-R03/FA-R10; **без** дублирования текста назначения в БД (при необходимости — нормализованный тип документа + хэш).

### 7. Тесты

- Юнит-тесты на **парсер шаблонов** с **синтетическими** строками (без данных клиента).
- Контрактные тесты: «валовая − комиссия = зачисление» с допуском **1,00**.
- Регресс по допускам месяца — опционально на зафиксированных **обезличенных** фикстурах.

### 8. Риски

- Изменение формата текста назначения банком → рост **неразобранных** строк.
- Сдвиг дат выписка vs **57.03** по дням → ложные «красные» дни без оконной политики.
- Смешение **91.02** (все банковские комиссии) с комиссией эквайринга — **не использовать** Дт **91.02** целиком как эталон комиссии эквайринга.

### 9. Решения, которые должен принять владелец

1. Утвердить **допуски** (рубли и % от эталона) и правило **«сверено по месяцу / по дням»**.
2. Утвердить **список шаблонов** распознавания эквайринга в S1 и порядок обработки **неразобранных** и **возвратов**.
3. Зафиксировать **НДС-шкалу** для сопоставления выписки и ОСВ.
4. Нужна ли в продукте **сверка по дням** обязательной или достаточно **месяца + флага качества**.
