# ADR-002 · Выручка из расчётов платёжного канала «эквайринг» (банковская выписка) (черновик)

**Статус:** черновик для владельца продукта и бухгалтера. **Без** кода и SQL.  
**Данные:** операционные файлы клиента только в `var/` (не в git).

**Рамка:** продукт для **рынка**; учёт строится на **бухгалтерских данных** (ОСВ, карточки, анализ счетов). Выписка — **вспомогательный канал** для канала **эквайринг** (транзит **57.03**). Иллюстрации на исторических выгрузках — **тестовый набор**, не норма для реализации под одну организацию. **НДС** согласуется с профилем организации — [ADR-003](ADR-003-organization-profile-and-tax-rules.md).

---

## Контекст

У многих организаций с безналичным приёмом **эквайринг** даёт **существенную долю** Кт **90.01**; точная величина задаётся **профилем и отраслью**, а не константой продукта. **ОСВ** (**57.03**, **90.01**) остаётся **эталоном учёта**. Банковская выписка (**ClientBank**, условное **S1**) даёт независимую линию: по строкам с **распознаваемым шаблоном** (без хранения текста назначения в git) извлекаются **валовая сумма**, **комиссия** и сверка с **зачислением** (сумма документа). В продукте — **агрегаты и признаки качества**.

---

## Решение (черновик)

### 1. Источник и классификация

- **Источник:** строки выписки (документы «поступило»), отфильтрованные по **согласованным шаблонам** (ключевые слова / правила на стороне импорта; перечень фиксируется в FA-R03 / FA-R06).
- **Признак в данных:** отметка вида **`revenue_from_payment_channel_statement`** (или аналог) + флаг **`derived_from_bank_statement`**, если агрегат по эквайрингу за период дополнительно сверен с выпиской, а не только с ОСВ.

### 2. Самоконтроль по строке

Для каждой принятой строки эквайринга: **валовая − комиссия (из разобранных полей назначения) = зачисление (сумма документа)** с допуском **до 1,00** (округления в тексте и в поле суммы). Строки вне допуска — **неразобранные** или ручное подтверждение (текст назначения в открытом виде в git **не** хранится; допустимы тип шаблона и хэш).

### 3. Допуски сверки с ОСВ (пилот)

Эталон по транзиту при наличии учёта: **Дт 57.03** (ОСВ за месяц).  
Эталон **комиссии эквайринга** для сравнения с суммами из выписки: **Дт 57.03 − сумма зачислений по принятым строкам эквайринга выписки за месяц** (при нулевых остатках **57.03** это соответствует разнице транзита и зачисления на **51**), **не** суммарный **Дт 91.02** по всем банковским комиссиям.

**Допуски только абсолютные (руб.); процентной альтернативы нет.**

| Уровень | Допуск |
| --- | --- |
| **Месяц, валовая** (выписка vs **Дт 57.03**) | ± **5,00** |
| **Месяц, комиссия** (выписка vs эталон **Дт 57.03 − зачисления**) | ± **10,00** |
| **День, валовая** (выписка vs **Дт 57.03** по дням, напр. детализация **57.03**) | ± **1,00** |

*Параметры пилота; **пересмотр после трёх месяцев** эксплуатации на разных банках и шаблонах назначений.*

На тестовом наборе **даты операций в выписке и даты движений по счёту 57.03 в учёте совпадали по календарному дню**; расхождения сумм укладывались в допуски **округления** (см. §3.1) **без** «окна ±1 день» и **без** статуса «перенос пачки».

### 3.1 Дата признания выручки эквайринга

- В **учёте** датой может быть **зачисление на расчётный счёт** (**51**) в соответствии с учётной политикой.
- В **тексте назначения** выписки часто присутствуют **даты операций эквайринга** (период, за который банк формирует пачку) — они **не обязаны** совпадать с датой проводки в **1С**.
- **Какую дату показывать** в управленческом слое (деньги vs начисление): **политика организации** — фиксируется в профиле / методичке бухгалтера ([ADR-003](ADR-003-organization-profile-and-tax-rules.md)); продукт не подменяет ответ бухгалтерии единой датой «автоматически».

**«Считаем сверенной»:**

- **Месяц:** валовая и комиссия в допуске **и** нет строк в статусе «спор» / «неразобрано», **или** есть подтверждение бухгалтера.
- **По дням:** для каждого календарного дня с движением **57.03** валовая в допуске **±1,00** (при совпадении дат выписки и учёта; иначе — сверка **только на уровне месяца** или явная политика организации из §3.1).

### 3.2 Приоритет источника

| Ситуация | Что показываем | Выписка |
| --- | --- | --- |
| Есть **ОСВ** (и при необходимости детализация **57.03**) | **Эталон — учёт (ОСВ)**; суммы эквайринга в пользовательском отчёте совпадают с учётом при прохождении допусков | **Контроль** и самоконтроль по строке (§2) |
| Нет полного учёта (**облако** без ОСВ, **книга/CSV** и т.п.) | Значение по **выписке** с признаком **`рассчитано_по_выписке`** и теми же **абсолютными** допусками §3 (без претензии к полноте как к ОСВ) | **Единственный** количественный источник сегмента |

### 4. Возвраты и спорные платежи

- **Возвраты / сторно:** отдельная категория; без согласованного знака в агрегате за день — `unavailable` для блока или дня.
- **Спорные:** не проходят самоконтроль или неизвестен шаблон — не входят в агрегат «по выписке» до разметки.

### 5. Влияние на контуры

- **Покрытие / ОПиУ:** при наличии ОСВ — см. **§3.2**; выписка без прохождения допусков не подменяет учёт; при сомнениях — `unavailable` (в т.ч. по правилам покрытия затрат / D4).
- **Дебиторка:** эквайринг **не создаёт** дебиторскую по **62.01**; контур **62/51** остаётся отдельным (FA-R03.1).
- **«Поступление не равно выручке»:** зачисление на **51** — **денежный поток**; **Дт 57.03** / **Кт 90.01** — **учётная выручка**; оба слоя показываются явно.
- **НДС:** шкала (с НДС / без / спецрежим) задаётся **[ADR-003](ADR-003-organization-profile-and-tax-rules.md)**; выписка и ОСВ сверяются в **одной согласованной шкале** за период.

### 6. Сущности и миграции (описание, без SQL)

- Учётный сегмент **«эквайринг за период»**: период, валовая, комиссия, зачисление, источник агрегата (`statement` / `ledger`), флаги полноты и допуска.
- Связь с импортом и закрытием периода — по FA-R03/FA-R10; **без** хранения полного текста назначения (при необходимости — код типа и хэш).

### 7. Тесты

- Парсер шаблонов — на **синтетических** строках.
- Контракт: «валовая − комиссия = зачисление» с допуском **1,00**.
- Регресс допусков — опционально на **обезличенных** фикстурах.

### 8. Риски

- Смена формата назначений банком → рост **неразобранных** строк.
- Сдвиг дат выписка vs **57.03** по дням → ложные отклонения без оконной политики.
- Путаница **91.02** (все банковские комиссии) с **комиссией эквайринга** — не использовать **Дт 91.02** целиком как эталон комиссии канала.

### 9. Решения владельца

1. Утвердить **абсолютные допуски** §3 и правило **«сверено по месяцу / по дням»** (дни — только при совпадении дат или отдельной политике §3.1).
2. Утвердить **шаблоны** распознавания и порядок **неразобранных** / **возвратов**.
3. Согласовать **НДС-шкалу** с [ADR-003](ADR-003-organization-profile-and-tax-rules.md).
4. Зафиксировать в профиле **политику даты** для отображения (§3.1).
