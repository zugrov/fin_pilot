# ADR-003 · Профиль организации и налоговые правила (черновик)

**Статус:** черновик для владельца продукта (рынок); **без** кода и SQL.  
**Данные клиента:** только учётные выгрузки и согласования вне git (`var/`).

**Решение владельца:** продукт ориентирован на **рынок**; учёт в системе строится **только** на **бухгалтерских данных** организации пользователя. Отдельная тестовая организация используется для приёмки и **не** задаёт специфику реализации «для одного заказчика» в ADR.

---

## 1. Назначение

Единый **профиль организации** задаёт допустимые сценарии расчётов, флаги качества (`unavailable`), разрез НДС и сопоставление с источниками (ОСВ, выписка, анализ счетов). **Закрытые периоды** не пересчитываются при смене профиля — действует снимок правил на дату закрытия.

---

## 2. Поля профиля (логический контракт)

| Поле | Смысл | Значение по умолчанию (черновик) | Пояснение |
| --- | --- | --- | --- |
| **org_form** | Орг. форма (ИП, ООО, АО, …) | `unspecified` до мастера | Влияет на доступные режимы и отчётность (вместе с матрицей §7). |
| **tax_system** | Система налогообложения | `unspecified` | Для рынка РФ в приоритете **УСН**; иные режимы — по мере поддержки. |
| **usn_tax_object** | Объект УСН | `unspecified` | **«Доходы»** / **«Доходы минус расходы»** — от фильтра расходов и контроля ПБУ. |
| **vat_status** | НДС | `unknown` | Варианты: **плательщик НДС**; **спец. ставки 5% / 7%** (режимы законодательства); **освобождение**; **не применяется** (в т.ч. УСН без НДС). |
| **vat_regime_detail** | Режим ведения НДС (если применим) | `unspecified` | **Плательщик с правом вычетов** (общий порядок) vs **спец. ставки 5%/7% без вычетов** — влияет на разрез счетов **19**/**68** и классификацию. |
| **vat_default_rate** | Ставка НДС «по умолчанию» для показа/сверки | `unspecified` | Заполняется **только** при **vat_status** = плательщик с общим порядком: **22**, **10**, **0** (строкой). При спец. ставках, освобождении и «не применяется» — **пусто** / `unspecified`. |
| **prices_include_vat** | Цены с НДС | `unknown` | Да/нет: согласование выручки, банка и ОСВ (**одна шкала** за период). |
| **vat_exemption_article_145** | Освобождение от НДС по ст. 145 НК РФ | `unknown` | Флаг **boolean** при освобождении; взаимоисключение с режимом «плательщик с вычетами» — по правилам валидации. |
| **is_new_organization** | «Новая организация» (нет выручки в прошлом году) | `unknown` | Если **да** — **prior_year_revenue_band** не задаётся; порог **20 млн** за предыдущий год считается **непревышенным** до подтверждения бухгалтером. |
| **revenue_recognition_method** | Метод признания выручки в учёте | `unknown` | Как в учётной политике (начисление / касса / иное); до заполнения — предупреждение. |
| **accounting_source** | Источник учёта | `unspecified` | **1С**, **облачная бухгалтерия**, **книга учёта / CSV** и т.д.; матрица §7. |
| **industry_sphere** | Сфера (торговля, услуги, производство, смеш.) | `unspecified` | Влияет на рекомендуемый **персональный список выгрузок** и контрольные счета. |
| **money_channels** | Каналы денег | `unspecified` | Банк, эквайринг, касса, проч.; для маршрутизации сверок (ОДДС vs ОПиУ). |
| **prior_year_revenue_band** | Диапазон выручки **прошлого** налогового года | `unknown` | Нужен для **порогов НДС при УСН** и проверки применимости ставок; ввод вручную или из внешнего подтверждения. |
| **month_close_policy** | Закрытие месяца в учёте | `unknown` | Дата/правило «месяц закрыт»; что запрещено после выгрузки. |
| **users_roles** | Пользователи (роли) | по политике продукта | Кто подтверждает профиль и изменения (**owner**, **accountant**, …). |

**Качество:** пока **vat_status** или критические поля `unspecified` / `unknown`, показываются предупреждения и при необходимости **`unavailable`** для налогово-зависимых разрезов (см. §5).

## 3. Версионирование и журнал изменений

- Каждая версия профиля: **`effective_from`** (дата вступления в силу), **автор**, **краткая причина** (без ПДн). Для **налоговых** и связанных с режимом полей — **`effective_from`** **не ранее первого числа месяца** (см. §6).
- **Черновик:** последняя **неподтверждённая** версия (`confirmed_at` пусто) **редактируется** до подтверждения; новая версия с другим `effective_from` создаётся только после подтверждения предыдущей.
- **Подтверждение:** отдельное действие **owner** / **accountant**; **`confirmed_at` / `confirmed_by` / `confirmed_role` ставятся один раз**; после этого снимок **неизменяем** (в т.ч. на уровне БД).
- **Минимум для подтверждения:** `org_form`, `tax_system`, `usn_tax_object` (если УСН), `vat_status` (и `vat_default_rate` при плательщике с общим порядком), `is_new_organization` **или** `prior_year_revenue_band`, `accounting_source`, `money_channels` (не только `unspecified`), `month_close_policy`, `revenue_recognition_method`. Уровень поддержки «не поддерживается» **не блокирует** подтверждение.
- **Журнал:** append-only; **изменение не затирает** применённость к закрытому периоду.
- Исторический период **P** использует **снимок** профиля с `effective_from ≤ начало P` (последняя актуальная на дату закрытия месяца в учёте). **Первая версия профиля действует на все более ранние периоды** (ретроактивно, если у организации нет версии с `effective_from` раньше **P**); **решение владельца** зафиксировать в данных при bootstrap/подтверждении.
- **Стартовый `effective_from` bootstrap-версии:** первое число календарного месяца **локального времени организации** (`companies.timezone`) по `companies.created_at` (в миграции backfill и в `create_company` — одна и та же формула).
- Если **последняя** версия на период **не подтверждена**, период считается **неподтверждённым** (защита пилота, план §2).

## 4. Справочник налоговых правил (версии)

Отдельный справочник **«версия норм»**: ставки, пороги, коэффициенты-дефляторы. Для каждой записи: **источник** (официальный), **дата проверки** в календаре команды.

### 4.1 Пороги НДС при УСН (ориентир **2026**, РФ)

Официальные формулировки и ссылки — **ФНС**; в продукте хранится **версия** справочника с `source_url` и `verified_at`.

**Правило применимости обязанности (упрощённо для подсказки в продукте, не замена консультации):**

- Налогоплательщик **не** обязан исчислять НДС, пока одновременно выполняется: **доход за предыдущий календарный год ≤ 20 млн руб.** (в порядке, установленном НК РФ) **и** **текущий** календарный год **ещё не превысил** **20 млн** руб. дохода (накопленно) — ориентир для мониторинга; точное определение базы и момента — по нормам и учёту.
- **Обязанность** считаться плательщиком НДС (без добровольного перехода) возникает **с первого числа месяца**, **следующего за месяцем**, в котором **превышен** порог **20 млн** по **текущему** году (каноническая формулировка — в НК РФ и разъяснениях ФНС).

**Дефлятор 1,090** (для **2026** по материалам ФНС): применяется **к порогам денежных сумм, к которым закон привязывает спец. ставки НДС** (базы **250 млн** и **450 млн**): **250 × 1,090 = 272,5 млн**; **450 × 1,090 = 490,5 млн**.

**Порог освобождения **20 млн** руб.** (до обязанности без добровольного перехода) **не** умножается на дефлятор — индексации этого порога в указанной логике **нет** (уточнять по актуальной редакции НК и письмам ФНС при релизе справочника).

| Параметр | Значение | Примечание |
| --- | --- | --- |
| Порог до обязанности (без добровольного перехода), «освобождение» | **20 млн** руб. — **без** дефлятора | Сверка с **prior_year_revenue_band**, **is_new_organization**, учётным доходом текущего года. |
| Верхняя граница для ставки **5%** (после вступления в обязанность) | **272,5 млн** руб. | **250 млн × 1,090** |
| Верхняя граница для ставки **7%** | **490,5 млн** руб. | **450 млн × 1,090** |
| Дефлятор | **1,090** | Только к порогам **250 / 450** млн, **не** к **20** млн |

### 4.2 Порог освобождения от НДС при УСН (**2027+**, решение владельца)

**Решение владельца:** порог освобождения от обязанности по НДС при УСН **сохраняется на уровне 20 млн руб.** — см. Федеральный закон от **04.07.2026 № 228-ФЗ** (изменения в ст. **145** НК РФ). В продукте и справочнике норм ориентир на **текст закона**; разъяснения ФНС — вспомогательные; при приёмке — дословная сверка с законом.

**Источники:**

- Текст закона (СПС Гарант): [base.garant.ru/414502711](https://base.garant.ru/414502711/)
- Разъяснения ФНС: [материал про 2027 год](https://www.nalog.gov.ru/rn11/news/activities_fts/16668026/); [график порогов](https://www.nalog.gov.ru/rn33/news/tax_doc_news/16636398/)

**Оговорка:** в региональных материалах ФНС формулировки границ лет **могут отличаться** (например, порог «за 2025–2029» в одном из публикаций). В продукте применяется **график по закону**; при расхождении с разъяснением — приоритет у **228-ФЗ**.

**График (упрощённо для подсказки, не замена консультации):**

| Условие | Порог (руб.) |
| --- | --- |
| Освобождение в году определяется **доходом за предыдущий год**: 2025–2028 | **20 млн** |
| То же для дохода **2029** года | **15 млн** |
| То же для дохода **2030** года и далее | **10 млн** |
| **Внутри** календарного года (накопленный доход): 2026–2029 | **20 млн** |
| Внутри года: **2030** | **15 млн** |
| Внутри года: **2031** и далее | **10 млн** |

**Момент обязанности:** при превышении порога внутри года — с **первого числа месяца, следующего за месяцем превышения** (каноническая формулировка — в НК РФ).

**Дефлятор УСН на 2027:** приказ Минэкономразвития от **21.10.2026 № 732** (зарегистрирован Минюстом **30.10.2026** № 88977, [официальная публикация](http://publication.pravo.gov.ru/document/0001202610300013)) — коэффициент **1,153**. Границы спец. ставок **5% / 7%** на 2027: **288,25 млн** (250 × 1,153) и **518,85 млн** (450 × 1,153). **Дефляторы на 2028 и 2029** отдельными приказами ещё **не установлены** — открытый вопрос до публикации.

**Справочник норм (продукт):**

- **2027-01-01 … 2027-12-31:** статус **`confirmed`** — порог **20 млн**, дефлятор **1,153**, базы **250 / 450** млн; источник — приказ № 732 (ссылка выше).
- **2028-01-01 … 2029-12-31:** **`partially_confirmed`** — порог **20 млн**; дефлятор и границы **5% / 7%** **не заполняются** до приказов на соответствующие годы.
- С **2030-01-01:** черновик **`needs_review`** без жёстких чисел до отдельной проверки графика снижения.

## 5. Матрица влияния настройки → расчёты, флаги, экраны

| Настройка | Влияние |
| --- | --- |
| **vat_status** | Разрез сумм с/без НДС; отображение цен; снятие **`vat_basis_unknown`** при значении **«не применяется»** или подтверждённом режиме спец. ставки. |
| **vat_regime_detail**, **vat_default_rate**, **prices_include_vat** | Согласование ОСВ, банка и отчётов; выбор подсказок по счетам **19** / **68**; фильтрация «лишних» вычетов при режиме **без вычетов**. |
| **vat_exemption_article_145** | Маршрутизация освобожденных операций; не смешивать с плательщиком с вычетами без явного сценария. |
| **is_new_organization** | Упрощение ввода порога **20 млн** до появления годовой базы (см. §4.1). |
| **usn_tax_object** | Доступность расходных статей при УСН; качество блока расходов. |
| **money_channels** | Включение сверок **эквайринг ↔ 57.03** ([ADR-002](ADR-002-acquiring-revenue-from-bank-statement.md)), касса, проч. |
| **revenue_recognition_method** | Сопоставление ОПиУ и ОДДС («поступления ≠ выручка»). |
| **accounting_source** | Допустимые форматы импорта и **персональный список выгрузок** ([FA-R03.2-export-checklist-by-profile.md](FA-R03.2-export-checklist-by-profile.md)). |

### 5.1 Налоговые платежи и секции ОДДС (подсказка по режиму)

В отчёте **ОДДС** классификация «операционные / инвестиционные / финансовые» должна быть согласована с **tax_system** и **vat_status**. Черновик соответствия (агрегаты без детализации проводок):

| Категория платежа (налог) | УСН (типично) | ОСНО (типично) |
| --- | --- | --- |
| УСН (аванс, доначисление) | Операционная (уплата «доход» / «доходы − расходы») | — |
| НДС (уплата / возмещение) | Если обязанность НДС при УСН — по политике; иначе **не** смешивать с «единым» блоком УСН | Операционная (при типовой привязке к текущей деятельности) |
| Налог на прибыль | — | Операционная (текущий налог) / уточнение по практике учёта |
| Взносы (страховые) | Операционная | Операционная |

Отображение в UI — только с **явной меткой** «упрощённая схема»; спорные случаи → **`unavailable`** или ручное правило.

### 5.2 Наборы правил классификации по профилю

По сочетанию **org_form × tax_system × vat_status × money_channels** подставляется **преднастроенный набор** правил классификации денежных потоков (шаблоны: эквайринг, зарплата, аренда, налоги, займы). **Подсказка** в продукте: «для вашего профиля рекомендован набор **N**»; пользователь может ослабить только в пределах прав ролей. Детализация — в FA-R03/F06, не в этом ADR.

## 6. Мастер при регистрации (черновик шагов)

1. Орг. форма и **ИНН** (валидация формата) — **обязательно**.
2. Система налогообложения и объект УСН (если УСН).
3. Статус НДС + при необходимости диапазон выручки прошлого года.
4. Источник учёта (1С / иное).
5. Каналы денег (мультивыбор).
6. Приглашение бухгалтера / **подтверждение** профиля (однократная отметка по минимуму полей из §3).

**По умолчанию:** консервативные `unknown` / `unspecified` с явными баннерами; стартовая версия при создании организации — **черновик** с теми же значениями по умолчанию.

**Черновик:** поля профиля можно менять, пока версия не подтверждена. **После подтверждения** — только новая версия с более поздним `effective_from`.

**Дата вступления изменений налоговых параметров профиля:** новая версия с **`effective_from` = первое число календарного месяца** (00:00 по часовому поясу организации), **если** иное не оговорено отдельным юридическим событием. Промежуточные даты внутри месяца для налоговых полей — **не** используются в черновике продукта (исключения только по явному решению владельца).

## 7. Матрица поддержки «форма × режим × источник учёта»

Легенда: **✓** целевой сценарий для релиза, **◐** частично (см. «что не покрыто»), **✗** не поддерживается (явно или `unavailable`).

Источники учёта:

- **1С** — типовая **1С:Бухгалтерия** (выгрузки отчётов, ClientBank).
- **Облако** — облачная бухгалтерия **с выгрузкой** в согласованных форматах (не обязательно 1С).
- **Книга / CSV** — упрощённый ввод (**кассовая книга**, **таблица оборотов**, **CSV** без полного плана счетов).

| org_form | tax_system | 1С | Облако | Книга / CSV |
| --- | --- | --- | --- | --- |
| **ООО** | **УСН** | ✓ | ◐ (зависит от экспорта) | ◐ только деньги + упрощённая сверка; **без** полной ОПиУ |
| **ООО** | **ОСНО** | ◐ | ◐ | ✗ |
| **ИП** | **УСН** | ✓ | ◐ | ◐ |
| **ИП** | **ОСНО** | ◐ | ◐ | ✗ |

**Что не покрыто при ОСНО (любой источник на раннем этапе):**

- **НДС с правом вычета** (входной НДС, восстановления, сложные счета **19**/**68**) — нужна полная выгрузка и отдельный пакет правил; до этого блок НДС **`unavailable`** или только оборотная сверка без «чистой» базы.
- **Налог на прибыль** (временные разницы, льготы ставки) — вне первого объёма; агрегаты по ОСВ без налогового **расчёта** в продукте.

**Фазирование:** рекомендуемый путь **УСН → переход на ОСНО** — отдельный **этап** продукта: новая версия профиля с **`effective_from`** = **первое число месяца** после смены режима; закрытые периоды на УСН **не пересчитываются**.

**Примеры систем учёта для ИП (не исчерпывающе):** **1С:Бухгалтерия**, **Контур.Эльба**, **Моё дело**, иные **ФНС-совместимые** облака с выгрузкой — совместимость по колонке **Облако** при наличии формата импорта.

| Режим / категория | 1С | Облако | Книга / CSV |
| --- | --- | --- | --- |
| **АУСН**, **ПСН (патент)**, **ЕСХН**, **самозанятые** (физлицо без полноценного юрлица в смысле продукта) | ✗ | ✗ | ✗ |

**Сообщение пользователю (черновик):** «Текущая версия FinPilot не поддерживает выбранную систему налогообложения или статус налогоплательщика. Укажите **УСН** или **ОСНО** для организации (**ИП** / **ООО**) с учётом в **1С** или облачной бухгалтерии с выгрузкой либо обратитесь в поддержку».

## 8. Сущности и миграции (описание)

- **OrganizationProfile** (версии с `effective_from`).
- **TaxRulesVersion** (справочник порогов/ставок с `source_url`, `verified_at`).
- Журнал изменений профиля — **существующий механизм аудита продукта** (не отдельная сущность «ProfileAuditLog» в этом ADR).
- **Миграции:** только перечень сущностей и **строковые/дата** поля в духе продукта; детали SQL — в отдельной задаче.

---

## 9. Тесты

- Контрактные: валидация переходов **vat_status**, несовместимость формы и режима.
- Снимки поведения экранов при **`vat_basis_unknown`** vs **«не применяется»**.
- Без фикстур с реальными ПДн; обезличенные профили.

---

## 10. Риски

- Устаревший справочник **2027+** → ошибочная подсказка по НДС.
- Несогласованность профиля и фактических выгрузок → ложное «зелёное» качество.
- Смешение **управленческого** и **налогового** разреза без явной метки.

---

## 11. Решения владельца

**Рекомендации редакции (для согласования):**

1. **Минимум полей** для первого релиза: **org_form**, **tax_system**, **vat_status**, **accounting_source**, **money_channels**, **ИНН**; остальные — по мере зрелости экранов.
2. **Справочник норм:** единственный **источник истины** — официальные материалы **ФНС** + ежеквартальная сверка редакции НК; записи с **«требуют проверки»** не давать без баннера.
3. **Налоговые подсказки:** **полный** текст — ролям **owner** и **accountant**; **viewer** — только агрегаты без интерпретации «что делать» (уточнить в RBAC).

**Решения владельца (фиксируются отдельно):**

1. Принять или скорректировать минимум полей п. выше.
2. Утвердить регламент обновления справочника §4 (ответственный, срок).
3. Утвердить матрицу видимости подсказок по ролям.
4. **Какие облачные системы учёта поддерживать после 1С** (приоритетный список поставщиков экспорта): выбрать **N** вендоров на **первый квартал** после релиза профиля (критерии: **стабильный экспорт** ОСВ/выписки, **объём пользователей**, готовность подписать формат с импортом); остальные — в backlog или **◐** по колонке **Облако** до появления формата.
