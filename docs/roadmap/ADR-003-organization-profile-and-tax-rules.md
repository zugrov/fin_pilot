# ADR-003 · Профиль организации и налоговые правила (черновик)

**Статус:** черновик для владельца продукта (рынок); **без** кода и SQL.  
**Данные клиента:** только учётные выгрузки и согласования вне git (`var/`).

**Решение владельца:** продукт ориентирован на **рынок**; учёт в системе строится **только** на **бухгалтерских данных** организации пользователя. Отдельная тестовая организация используется для приёмки и **не** задаёт специфику реализации «для одного заказчика» в ADR.

---

## 1. Назначение

Единый **профиль организации** задаёт допустимые сценарии расчётов, флаги качества (`unavailable`), разрез НДС и сопоставление с источниками (ОСВ, выписка, анализ счетов). **Закрытые периоды** не пересчитываются при смене профиля — действует снимок правил на дату закрытия.

---

## 2. Поля профиля (логический контракт)

| Поле | Смысл | Значение по умолчанию (черновик) | Пояснение |
| --- | --- | --- | --- |
| **org_form** | Орг. форма (ИП, ООО, АО, …) | `unspecified` до мастера | Влияет на доступные режимы и отчётность (вместе с матрицей §8). |
| **tax_system** | Система налогообложения | `unspecified` | Для рынка РФ в приоритете **УСН**; иные режимы — по мере поддержки. |
| **usn_tax_object** | Объект УСН | `unspecified` | **«Доходы»** / **«Доходы минус расходы»** — от фильтра расходов и контроля ПБУ. |
| **vat_status** | НДС | `unknown` | Варианты: **плательщик НДС**; **спец. ставки 5% / 7%** (режимы законодательства); **освобождение**; **не применяется** (в т.ч. УСН без НДС). |
| **revenue_recognition_method** | Метод признания выручки в учёте | `accrual_accounting` | Совпадение с **методом в учётной политике** (начисление vs иной порядок по договору — уточняется). |
| **accounting_source** | Источник учёта | `1c` (пример) | План счетов и выгрузки; матрица §8. |
| **industry_sphere** | Сфера (торговля, услуги, производство, смеш.) | `unspecified` | Влияет на рекомендуемый **персональный список выгрузок** и контрольные счета. |
| **money_channels** | Каналы денег | `unspecified` | Банк, эквайринг, касса, проч.; для маршрутизации сверок (ОДДС vs ОПиУ). |
| **prior_year_revenue_band** | Диапазон выручки **прошлого** налогового года | `unknown` | Нужен для **порогов НДС при УСН** и проверки применимости ставок; ввод вручную или из внешнего подтверждения. |
| **month_close_policy** | Закрытие месяца в учёте | `unknown` | Дата/правило «месяц закрыт»; что запрещено после выгрузки. |
| **users_roles** | Пользователи (роли) | по политике продукта | Кто подтверждает профиль и изменения (**owner**, **accountant**, …). |

**Качество:** пока **vat_status** или критические поля `unspecified` / `unknown`, показываются предупреждения и при необходимости **`unavailable`** для налогово-зависимых разрезов (см. §7).

---

## 3. Версионирование и журнал изменений

- Каждая версия профиля: **`effective_from`** (дата вступления в силу), **автор**, **краткая причина** (без ПДн).
- **Журнал:** append-only; **изменение не затирает** применённость к закрытому периоду.
- Исторический период **P** использует **снимок** профиля с `effective_from ≤ начало P` (последняя актуальная на дату закрытия месяца в учёте).

---

## 4. Справочник налоговых правил (версии)

Отдельный справочник **«версия норм»**: ставки, пороги, коэффициенты-дефляторы. Для каждой записи: **источник** (официальный), **дата проверки** в календаре команды.

### 4.1 Пороги НДС при УСН (ориентир **2026**, РФ)

По данным **ФНС** (формулировки доводятся до ссылок на первоисточники при утверждении; здесь — рабочие числа для продукта):

| Параметр | Значение | Примечание |
| --- | --- | --- |
| Порог **до обязанности** стать плательщиком НДС (без добровольного перехода) | **20 млн** руб. выручки за год (с учётом правил закона) | Сопоставление с **prior_year_revenue_band** и накопленным учётом. |
| Ставка **5%** | до **272,5 млн** руб. | После превышения порога вступления в обязательный НДС (логика применения — по нормам года). |
| Ставка **7%** | до **490,5 млн** руб. | Следующая ступень по нормам года. |
| Дефлятор | **1,090** | Индексация порога **20 млн** — по правилам года (проверка при релизе справочника). |

### 4.2 Годы **2027+**

Пороги, ставки и дефлятор помечаются в справочнике как **«требуют проверки»** — в открытых источниках возможны расхождения; до обновления записи продукт не подсказывает «жёсткую» применимость без ручного подтверждения бухгалтером.

## 5. Матрица влияния настройки → расчёты, флаги, экраны

| Настройка | Влияние |
| --- | --- |
| **vat_status** | Разрез сумм с/без НДС; отображение цен; снятие **`vat_basis_unknown`** при значении **«не применяется»** или подтверждённом режиме спец. ставки. |
| **usn_tax_object** | Доступность расходных статей при УСН; качество блока расходов. |
| **money_channels** | Включение сверок **эквайринг ↔ 57.03** ([ADR-002](ADR-002-acquiring-revenue-from-bank-statement.md)), касса, проч. |
| **revenue_recognition_method** | Сопоставление ОПиУ и ОДДС («поступления ≠ выручка»). |
| **accounting_source** | Допустимые форматы импорта и **персональный список выгрузок** ([FA-R03.2-export-checklist-by-profile.md](FA-R03.2-export-checklist-by-profile.md)). |

---

## 6. Мастер при регистрации (черновик шагов)

1. Орг. форма и **ИНН** (валидация формата) — **обязательно**.
2. Система налогообложения и объект УСН (если УСН).
3. Статус НДС + при необходимости диапазон выручки прошлого года.
4. Источник учёта (1С / иное).
5. Каналы денег (мультивыбор).
6. Приглашение бухгалтера / подтверждение профиля.

**По умолчанию:** консервативные `unknown` / `unspecified` с явными баннерами. **Что можно менять позже:** все поля, кроме иммутабельных идентификаторов; смена после закрытия периода создаёт новую **версию** с **`effective_from`**, без перезаписи старых отчётов.

---

## 7. Матрица поддержки «форма × режим × источник учёта»

Легенда: **✓** поддерживается в дорожной карте, **◐** частично / только учёт без налогового сценария, **✗** не поддерживается (явный отказ или `unavailable`).

| org_form / tax_system | 1С (типовая) | Иной учёт (ручной CSV — будущее) |
| --- | --- | --- |
| ИП / УСН | ✓ | ◐ |
| ООО / УСН | ✓ | ◐ |
| ООО / ОСН + НДС | ◐ | ✗ |
| … | … | … |

Точное заполнение — по продуктовому scope; в репозитории хранится **принцип**: любая ячейка **✗** получает понятное сообщение и не ведёт к «тихим» нулям.

---

## 8. Сущности и миграции (описание)

- **OrganizationProfile** (версии с `effective_from`).
- **TaxRulesVersion** (справочник порогов/ставок с `source_url`, `verified_at`).
- **ProfileAuditLog** (кто/когда/что).
- **Миграции:** только перечень сущностей и **строковые/дата** поля в духе продукта; детали SQL — в отдельной задаче.

---

## 9. Тесты

- Контрактные: валидация переходов **vat_status**, несовместимость формы и режима.
- Снимки поведения экранов при **`vat_basis_unknown`** vs **«не применяется»**.
- Без фикстур с реальными ПДн; обезличенные профили.

---

## 10. Риски

- Устаревший справочник **2027+** → ошибочная подсказка по НДС.
- Несогласованность профиля и фактических выгрузок → ложное «зелёное» качество.
- Смешение **управленческого** и **налогового** разреза без явной метки.

---

## 11. Решения владельца

1. Утвердить **обязательный минимум** полей для первого релиза профиля.
2. Утвердить **источник истины** для справочника норм (ФНС + периодичность обновления).
3. Зафиксировать, показываем ли **налоговые** подсказки пользователю или только бухгалтеру.
