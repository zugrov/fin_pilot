# FA-R06.2 · план контурной ОПиУ (пилот, без кода)

**Статус:** план для согласования с бухгалтером; **не** запись в продукт.  
**Данные:** только локальные выгрузки 1С в `var/` (gitignored). **ТОПКОМ** — чувствительные данные, не в git.

**Цель:** связать **начисленную выручку и расходы** (счета 90/91/20/26/44 и субсчета по политике учёта) с **ОДДС** и границами FA-R06.2 для закрытого месяца (пилот).

---

## 1. Эталон из ОСВ (август / сентябрь 2026)

Для каждого месяца снять **агрегаты по счетам** (итоги по Дт/Кт или обороты — по формату выгрузки), **без строк контрагентов и назначений** в протоколе git:

| Код | Ожидаемый агрегат |
| --- | --- |
| **90.x** | Выручка, себестоимость, прочие доходы/расходы по политике |
| **91.x** | Прочие доходы/расходы (если выделены) |
| **20** | Прямые/производственные затраты (по карте счетов организации) |
| **26** | Общехозяйственные |
| **44** | Расходы на продажу |

**Критерий полноты месяца:** начало — 1-е число, конец — последний календарный день; итоги согласуются с «Итого» в файле ОСВ.

### 1.1 Состав выручки (пилот, по ОСВ S3)

Для закрытого месяца в выгрузке проверяется **тождество по оборотам** (все суммы — из строки счёта в ОСВ, без контрагентов и назначений в git):

**Кт 90.01 (за месяц) = Дт 62.01 + Дт 57.03 + «прямые поступления на 90.01»**

- **Дт 62.01** — отгрузка/реализация в части дебиторской задолженности покупателей.
- **Дт 57.03** — выручка, прошедшая через эквайринг (деньги пока на транзитном счёте).
- **Третья часть** — остаток до равенства с **Кт 90.01**; в практике пилота это соответствует прямому зачёту на **90.01.1** (или иному субсчёту прямой выручки по политике учёта) и **не** дублирует строки эквайринга и 62.01.

Локальная проверка на образцах **2026-08** и **2026-09** (только `var/`, не в git): равенство выполняется с допуском **0,00**; доли трёх компонент сохраняются между месяцами на уровне процентов (для пилота — контроль структуры, не цель оптимизации).

### 1.2 Журнал реализаций (S11) и счёт 62

**Журнал реализаций по выгрузкам пилота отражает операции, корреспондирующие с 62.01**, а не полный **Кт 90.01**: поступления через **57.03** и прямые проводки на **90.01.1** в журнале реализаций **не покрываются** и берутся из **ОСВ** и/или документов эквайринга. При проектировании отчёта и импорта нельзя считать S11 единственным источником выручки месяца.

| Источник | Что даёт | Связь с ОПиУ |
| --- | --- | --- |
| Начисления зарплаты / страховых взносов | 20/26/44, 70/69 | Не все платежи видны в банке в том же месяце |

Эти потоки должны быть явно **помечены в плане сверки** «ОПиУ ↔ деньги», иначе ОДДС «уедет» от P&L.

## 3. Связь с ОДДС (cash ↔ accrual)

| Контур | Проверка |
| --- | --- |
| **Выручка** | 90.01/62 ↔ поступления 51 с корр. 62.xx (уже в FA-R03.1; не смешивать с «чистой» выручкой ОПиУ без учёта НДС/отгрузки) |
| **Операционные платежи** | 51/52 ↔ 20/26/44/60/76 по факту оплаты |
| **Авансы** | 60/62 на балансе vs факт расхода в месяце |

**Правило:** поступление **не равно** выручке; выплата **не равна** расходу в ОПиУ в том же месяце — фиксировать лаги в таблице расхождений.

## 4. Продукт (FA-R06.2): источники, отчёт, правило D4

**Источники данных (после FA-R03.x / согласованной загрузки):**

| Источник | Роль в продукте |
| --- | --- |
| **ОСВ S3** (счета 90.xx, 20, 26, 44, 62.01/62.02, 57.03) | Эталон оборотов и сальдо по счетам; основа для выручки по формуле §1.1 и для блока расходов |
| **Анализ счёта 90.01** (документы/субсчета) | Дробление «третьей доли» и прямой выручки, согласование с политикой НДС |
| **Документы эквайринга** (или выписки по 57.03) | Пояснение дней и сумм при расхождении Дт 57.03 ↔ банк; не подменяют ОСВ |
| **S11 (журнал реализаций)** | Только сегмент **62.01**; используется как вспомогательный контроль, не как полный Кт 90.01 |

**Что попадает в продукт (логика, без привязки к коду):** агрегированные суммы по источникам выручки (три компоненты §1.1), статьи расходов из согласованной карты счетов, признаки качества данных и ссылка на закрытый период.

**Структура отчёта (пилот):** блок **«Выручка по источникам»** (Дт 62.01, Дт 57.03, прямое Кт 90.01.x), блок **«Расходы по статьям»** (из ОСВ по политике пилота), блок **«Сверка с ОДДС»** (лаги, без подмены начисления деньгами).

**Правило D4:** **прибыль (или «итог периода») не показывается**, если для месяца **нет покрытия затрат** — то есть не согласован полный набор статей расходов / карта счетов или остались неразрешённые расхождения ОСВ ↔ источники выше согласованного допуска. В UI — явный статус `unavailable` или аналог, а не ноль.

**Критерии приёмки на закрытом месяце:** период полный; формула §1.1 с допуском **0,00**; для расходов — суммы по статьям согласованы с бухгалтером; D4 соблюдён; без записи в продуктивный tenant без отдельного «ок».

**Миграции БД:** только по отдельной спецификации FA-R06.2 (в репозитории — перечень сущностей и nullable/флаги качества); **в этом документе — без SQL**, только описательно: хранение периода, агрегатов выручки по трём источникам, статей расходов, признака закрытия и блокировки показа «прибыли» при D4.
