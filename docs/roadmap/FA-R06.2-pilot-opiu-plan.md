# FA-R06.2 · план контурной ОПиУ (пилот, без кода)

**Статус:** план для согласования с бухгалтером; **не** запись в продукт.  
**Данные:** только локальные выгрузки 1С в `var/` (gitignored). Персональные и учётные данные **не** в git.

**Цель:** связать **начисленную выручку и расходы** (счета 90/91/20/26/44 и субсчета по политике учёта) с **ОДДС** и границами FA-R06.2 для закрытого месяца (**пилот на тестовом наборе владельца**; продукт ориентирован на **рынок**, не на одну организацию).

**Источники:** только **бухгалтерский учёт** (отчёты 1С, выписки, ОСВ). **Биллинг продукта (SaaS)** к расчётам выручки организации **не относится**.

---

## 1. Эталон из ОСВ (август / сентябрь 2026)

Для каждого месяца снять **агрегаты по счетам** (итоги по Дт/Кт или обороты — по формату выгрузки), **без строк контрагентов и назначений** в протоколе git:

| Код | Ожидаемый агрегат |
| --- | --- |
| **90.x** | Выручка, себестоимость, прочие доходы/расходы по политике |
| **91.x** | Прочие доходы/расходы (если выделены) |
| **20** | Прямые/производственные затраты (по карте счетов организации) |
| **26** | Общехозяйственные |
| **44** | Расходы на продажу |

**Критерий полноты месяца:** начало — 1-е число, конец — последний календарный день; итоги согласуются с «Итого» в файле ОСВ.

### 1.1 Состав выручки (пилот, по ОСВ S3 и карточке 51)

Для закрытого месяца проверяются **тождества по оборотам** (ОСВ — строки счетов; третья доля — **агрегат по карточке 51** по корреспонденции, без контрагентов и текстов назначений в git):

**Кт 90.01 = Дт 62.01 + Дт 57.03 + (поступления на 51 с корр. 90.01.1)**.

- **Дт 62.01** — отгрузка/реализация в части дебиторской задолженности покупателей (ОСВ).
- **Дт 57.03** — выручка, прошедшая через эквайринг (транзит), до зачисления на расчётный счёт (ОСВ).
- **Третья доля** — сумма **поступлений на счёт 51** за месяц по **карточке 51**, где корреспондирующий счёт **90.01.1** (прямая выручка без цепочки 62/57). На **локальном тестовом наборе** владельца (пилот): **9 551,00** (2026-08) и **13 350,00** (2026-09); совпадение **Кт 90.01** с суммой трёх слагаемых — **0,00**.

### 1.2 Журнал реализаций (S11) и счёт 62

**Гипотеза (до получения выгрузки S11):** журнал реализаций покрывает преимущественно цепочку с **62.01**, а не полный **Кт 90.01**: поступления через **57.03** и поступления с корр. **90.01.1** в журнале реализаций, как правило, **не дублируют** полный состав выручки и должны подтверждаться **ОСВ** и банковскими источниками. После приёма **S11** — перепроверить по файлу и снять пометку «гипотеза».

### 1.3 Эквайринг: связь 57.03, 90.01 и 51 (для сверки и продукта)

В закрытом месяце на образцах выполняется проверка (ОСВ **S3**):

**Дт 57.03 / Кт 90.01 = Кт 57.03 (зачисление с транзита на 51) + Дт 91.02**,

где **Дт 91.02** отражает **банковскую комиссию и комиссию эквайринга** (в т.ч. проводки из карточки **51** с корр. **91.02** на образцах: **11 530,19** за 2026-08 и **12 961,10** за 2026-09). Сальдо **57.03** на начало и конец месяца — **нулевое**.

Численно (ОСВ **S3**, без назначений): **август** Дт **57.03** **1 146 114,86** = Кт **57.03** (перевод с транзита на **51**) **1 115 553,39** + Дт **91.02** **30 561,47**; **сентябрь** **1 142 709,83** = **1 112 363,52** + **30 346,31** — с допуском **0,00** по строкам счетов.

Для продукта: блок эквайринга опирается на **ОСВ 57.03 / 90.01 / 91.02**; выписка **S1** — **самоконтроль** «валовая − комиссия (из текста назначения) = зачисление» по платежам эквайринга (шаблоны — с бухгалтером).

## 2. Источники начисленных расходов (вне ОДДС)

| Источник | Что даёт | Связь с ОПиУ |
| --- | --- | --- |
| Начисления зарплаты / страховых взносов | 20/26/44, 70/69 | Не все платежи видны в банке в том же месяце |

Эти потоки должны быть явно **помечены в плане сверки** «ОПиУ ↔ деньги», иначе ОДДС «уедет» от P&L.

## 3. Связь с ОДДС (cash ↔ accrual)

| Контур | Проверка |
| --- | --- |
| **Выручка** | 90.01/62 ↔ поступления 51 с корр. 62.xx (уже в FA-R03.1; не смешивать с «чистой» выручкой ОПиУ без учёта НДС/отгрузки) |
| **Операционные платежи** | 51/52 ↔ 20/26/44/60/76 по факту оплаты |
| **Авансы** | 60/62 на балансе vs факт расхода в месяце |

**Правило:** поступление **не равно** выручке; выплата **не равна** расходу в ОПиУ в том же месяце — фиксировать лаги в таблице расхождений.

## 4. Продукт (FA-R06.2): источники, отчёт, правило D4

**Источники данных (после FA-R03.x / согласованной загрузки):**

| Источник | Роль в продукте |
| --- | --- |
| **ОСВ S3** (счета 90.xx, 20, 26, 44, 62.01/62.02, 57.03) | Эталон оборотов и сальдо по счетам; основа для выручки по формуле §1.1 и для блока расходов |
| **Карточка 51** | Третья доля выручки: **поступления с корр. 90.01.1** (агрегат за месяц) |
| **Анализ счёта 90.01** (документы/субсчета) | Дробление «третьей доли» и прямой выручки, согласование с политикой НДС |
| **Банковская выписка (S1), фрагмент эквайринга** | Дополнительный контроль по **шаблонам** строк: **валовая сумма** и **комиссия**; самоконтроль «валовая − комиссия = зачислено на 51»; **не** подменяет ОСВ при расхождении (см. [ADR-002](ADR-002-acquiring-revenue-from-bank-statement.md)) |
| **ОСВ / движение 57.03** (в т.ч. S12) | Эталон дней и Дт 57.03; сверка с агрегатами эквайринга из S1 |
| **S11 (журнал реализаций)** | Ожидаемо только цепочка **62.01** (см. §1.2); не полный Кт 90.01 |

**Что попадает в продукт (логика, без привязки к коду):** агрегированные суммы по источникам выручки (три компоненты §1.1), статьи расходов из согласованной карты счетов, признаки качества данных и ссылка на закрытый период.

**Структура отчёта (пилот):** блок **«Выручка по источникам»** (Дт 62.01, Дт 57.03, прямое Кт 90.01.x), блок **«Расходы по статьям»** (из ОСВ по политике пилота), блок **«Сверка с ОДДС»** (лаги, без подмены начисления деньгами).

**Правило D4:** **прибыль (или «итог периода») не показывается**, если для месяца **нет покрытия затрат** — то есть не согласован полный набор статей расходов / карта счетов или остались неразрешённые расхождения ОСВ ↔ источники выше согласованного допуска. В UI — явный статус `unavailable` или аналог, а не ноль.

**Критерии приёмки на закрытом месяце:** период полный; формула §1.1 с допуском **0,00**; для расходов — суммы по статьям согласованы с бухгалтером; D4 соблюдён; без записи в продуктивный tenant без отдельного «ок».

**Миграции БД:** только по отдельной спецификации FA-R06.2 (в репозитории — перечень сущностей и nullable/флаги качества); **в этом документе — без SQL**, только описательно: хранение периода, агрегатов выручки по трём источникам, статей расходов, признака закрытия и блокировки показа «прибыли» при D4.

## 5. Вопросы к бухгалтеру (зафиксировать ответы в `var/…`, не в git)

1. **Политика:** какие субсчета входят в «операционные расходы» пилота vs вне scope (фин., прочие)?
2. **НДС:** выручка и расходы в управленческом срезе — с НДС или без; как согласовать с банком?
3. **Распределение 26/44 на продукт/период:** одна база или несколько?
4. **Закрытие месяца:** дата «закрыт» в 1С; какие корректировки после выгрузки недопустимы?
5. **Связанные стороны:** нужны ли отдельные счета/аналитика (без ПДн в git)?
6. **57.03 ↔ 90.01:** подтвердить, что типовой шаблон проводок по эквайрингу соответствует схеме §1.3 (при необходимости — пример документа **в `var/`**, не в git).
7. **90.01:** предоставить **анализ счёта 90.01 по документам** за пилотный месяц (для расшифровки «прямой» доли и субсчетов).
8. **62.01 / 62.02:** выгрузить **ОСВ 62.01 и 62.02 за сентябрь** (аналог августа), чтобы контроль **S9 = S9a + S9b** и сверки с S3 выполнялись в обоих месяцах на одном уровне детализации.

| Этап | Содержание | Критерий «принято» |
