# P3 · Спецификация мастера профиля организации

**Статус:** спецификация (без кода), этап 1.  
**Основание:** [ADR-003](ADR-003-organization-profile-and-tax-rules.md) §2, §3, §6, §7; [profile-implementation-plan.md](profile-implementation-plan.md) §9; API P2a/P2b; [FA-R03.2](FA-R03.2-export-checklist-by-profile.md).

**Контекст API (уже есть):**

| Метод | Путь |
| --- | --- |
| GET | `/api/v1/companies/{company_id}/organization-profile?period=YYYY-MM-01` |
| GET | `/api/v1/companies/{company_id}/organization-profile/versions` |
| PATCH | `/api/v1/companies/{company_id}/organization-profile/draft` |
| POST | `/api/v1/companies/{company_id}/organization-profile/versions` |
| POST | `/api/v1/companies/{company_id}/organization-profile/versions/{version_id}/confirm` |
| GET | `/api/v1/tax-norms/current?as_of=YYYY-MM-DD` |

ИНН хранится на **компании** (`PATCH /api/v1/companies/{company_id}`), валидируется при сохранении профиля.

**Контекст UI (сейчас):** роутов профиля нет; повторно использовать `Shell`, `Banner`, `KpiCard`, `StatusChip`, `EmptyState`, `PeriodPicker`, паттерны `ClassificationPage` / `SalesPage` (React Query, `CompanyWritePicker`, ошибки `WalletRequestError`, idempotency через `salesPlanForm`).

## 1. Точка входа и состояния

### 1.1 Когда показывать мастер

| Сценарий | Триггер | Поведение |
| --- | --- | --- |
| **Первый вход после создания организации** | Пользователь owner/accountant впервые выбрал компанию; `profile_unconfirmed: true` на GET профиля | Мягкое предложение: баннер на **Обзоре** + ссылка «Настроить профиль»; **не** блокировать навигацию (plan §9). Опционально deep-link `?wizard=1` при создании компании (решение владельца — §11). |
| **Неподтверждённый профиль** | `is_confirmed: false` у последней версии | Баннер **warn** на Обзоре: «Профиль организации не подтверждён». Текст: налоговые подсказки и часть разрезов могут быть неточными до подтверждения. CTA → мастер (шаг 1 или последний сохранённый). |
| **Повторный вход для правки** | Есть неподтверждённый **черновик** последней версии | Мастер открывается на черновике; индикатор «Черновик». |
| **Смена режима после подтверждения** | Последняя версия **подтверждена** | Кнопка «Изменить режим с даты…» → **не** PATCH черновика подтверждённой версии, а **POST versions** с `effective_from` = первое число месяца и полным снимком + `change_reason`. Затем черновик новой версии → снова подтверждение. |

### 1.2 Права

| Роль | Чтение | Запись (PATCH draft, POST version, confirm) |
| --- | --- | --- |
| **owner** | да | да, при подтверждённой почте |
| **accountant** | да | да, при подтверждённой почте |
| **viewer** | да (GET профиль, версии) | **нет**; мастер в режиме только просмотра (поля disabled, без CTA сохранения) |
| **operator / billing_manager** | по политике tenant (как companies) | **нет** на профиль |

Запись: `403 forbidden` / `403 email_not_verified`. CSRF на мутациях, `Idempotency-Key` на POST version и confirm.

### 1.3 Маршрутизация (предложение)

- `/settings/org-profile` — мастер и карточка после подтверждения.
- Пункт навигации: группа «Настройки» (новая) или ссылка из баннера Обзора (минимум P3 — баннер + settings).

## 2. Шаги мастера (6)

Общие правила шага:

- Прогресс: «Шаг N из 6», кнопки «Назад» / «Далее».
- На «Далее»: PATCH draft только **изменённых** полей шага + опционально `change_reason` (накопительно в локальном state; на submit шага — краткая строка, ≤ 500 символов, подсказка «без персональных данных»).
- Значения по умолчанию — как bootstrap ADR-003: `unspecified` / `unknown`, кроме `money_channels: ["unspecified"]`.

### Шаг 1 · Форма и ИНН

| Поле | API | Варианты | По умолчанию | Пояснение пользователю |
| --- | --- | --- | --- | --- |
| **org_form** | snapshot | ИП, ООО, АО, не выбрано | `unspecified` | Как зарегистрирована организация. Влияет на допустимые режимы налогообложения. |
| **inn** | `company.inn` | 10 или 12 цифр | из компании | Идентификатор в налоговой. Показать текущий ИНН; редактирование через сохранение компании (тот же экран). При ошибке контрольной суммы — подсветка поля. |

**ИНН:** коды `inn_not_digits`, `inn_invalid_length`, `inn_checksum_mismatch` (см. §4).

### Шаг 2 · Система налогообложения

| Поле | Варианты | Пояснение |
| --- | --- | --- |
| **tax_system** | УСН, ОСНО, АУСН, ПСН, ЕСХН, самозанятый, не выбрано | Как платите налоги. **АУСН, ПСН, ЕСХН, самозанятые** — продукт показывает «режим не поддерживается» (support), отчёты ограничены. |
| **usn_tax_object** | Доходы / Доходы минус расходы / не применимо | Только если **УСН**: что учитываете при расчёте налога. |

Сразу после выбора — **баннер support** (`support_level`, `support_code` из ответа PATCH/GET).

### Шаг 3 · НДС и пороги

Загрузка **`GET /tax-norms/current?as_of=`** (дата = сегодня в TZ организации или выбранный `effective_from` при смене режима).

| Поле | Варианты | Пояснение |
| --- | --- | --- |
| **vat_status** | Неизвестно; НДС не применяется; Плательщик НДС; Спец. ставки 5% и 7%; Освобождение | **Не применяется** — УСН без обязанности по НДС. **Спецставки** — НДС уже в цене (5/105, 7/107), отдельная ставка в профиле не хранится. **Освобождение** — нулевая ставка по закону; опционально ст. 145 (чекбокс). |
| **vat_regime_detail** | С вычетами / Спец. без вычетов / не указано | Для плательщика или спецрежима. |
| **vat_default_rate** | 22, 10, 0 | Только **плательщик** с общим порядком. |
| **prices_include_vat** | Да / Нет / Неизвестно | Совпадают ли цены в учёте с НДС внутри. |
| **vat_exemption_article_145** | да/нет | Только при **освобождении**: освобождение по ст. 145 НК РФ. |
| **is_new_organization** | да/нет | Нет выручки в прошлом году — порог 20 млн считается не превышенным до уточнения. |
| **prior_year_revenue_band** | Диапазоны до 20 млн, 20–272,5 млн, … | Если организация **не новая** — для подсказок по НДС при УСН. |

**Справочник на экране** (read-only блок):

- Порог освобождения от НДС при УСН (`usn_vat_exemption_threshold_rub`).
- Потолки для 5% / 7% (`computed_special_cap_*`), дефлятор.
- Ставки `vat_rates_general_percent`, `vat_rates_special_percent`; доли 22/122, 5/105… из `vat_calculated_rates`.

Если `needs_review_banner: true` (`status` = `partially_confirmed` | `needs_review`) — **Banner tone=warn**, label «Справочник на проверке»: цифры ориентиры, уточните у бухгалтера.

### Шаг 4 · Источник учёта

| Поле | Варианты | Пояснение |
| --- | --- | --- |
| **accounting_source** | 1С; Облачная бухгалтерия; Книга / CSV; не выбрано | Откуда будут выгрузки. **Облако** и **книга** — частичная поддержка; **ОСНО + книга** — не поддерживается. |

### Шаг 5 · Каналы денег и сфера

| Поле | Варианты | Пояснение |
| --- | --- | --- |
| **money_channels** | Банк, эквайринг, касса, прочее (мультивыбор) | Откуда реально приходят и уходят деньги. Без выбора — нельзя подтвердить профиль. |
| **industry_sphere** | Торговля, услуги, производство, смешанная, не выбрано | Влияет на рекомендуемые выгрузки (FA-R03.2) и контроль затрат. |

### Шаг 6 · Закрытие месяца, выручка, сводка, подтверждение

| Поле | Варианты | Пояснение |
| --- | --- | --- |
| **month_close_policy** | Конец календарного месяца; Вручную; Иное; не выбрано | Когда месяц в учёте считается закрытым. |
| **revenue_recognition_method** | Начисление; Кассовый метод; Иное; не выбрано | Как в учётной политике признаётся выручка (поступления ≠ выручка). |

**Итоговая сводка** (read-only): все поля русскими подписями; блок support; **персональный список выгрузок** (§7); список **недостающих полей** из `field_errors._confirm_minimum` и прочих ключей при пробной валидации или ответе `400 profile_confirm_incomplete`.

**Подтверждение:** кнопка «Подтвердить профиль» → POST confirm + Idempotency-Key; поле `change_reason` обязательно (≤ 500).

## 3. Поведение

| Требование | Реализация |
| --- | --- |
| **Автосохранение** | PATCH draft при переходе «Далее» и при debounced blur на критичных полях (опционально 800 ms; минимум — по шагам). Показ «Сохранено» / «Сохраняем…». |
| **Назад** | Локальный state + данные с сервера; без потери при возврате. |
| **Выход** | Закрытие мастера → Обзор; черновик на сервере сохранён. |
| **Индикатор** | Chip: «Черновик» / «Подтверждён …» (дата из `confirmed_at`). |
| **Сводка перед confirm** | Client-side `validate_confirm_readiness` зеркалить по ответу API; при 400 показать `details.field_errors`. |
| **Новая версия** | Отдельный flow: выбор `effective_from` (месяц, ≥ следующий после последней подтверждённой), POST versions, затем шаги 1–6 с предзаполнением. |

## 4. Сообщения пользователю

Формат ошибок API: `{ "code", "message", "details": { "field_errors": { "поле": ["код", …] } } }`.

### 4.1 Коды API (верхний уровень)

| code | Текст для UI |
| --- | --- |
| `profile_validation_failed` | Проверьте выделенные поля. Данные не сохранены. |
| `profile_confirm_incomplete` | Не хватает данных для подтверждения. Заполните поля из списка ниже. |
| `profile_version_immutable` | Эта версия уже подтверждена и не редактируется. Создайте новую версию с даты изменения. |
| `already_confirmed` | Версия уже подтверждена. |
| `not_latest_version` | Редактировать или подтверждать можно только последнюю версию профиля. |
| `draft_exists` | Сначала завершите или подтвердите текущий черновик. |
| `effective_from_not_after_latest` | Дата новой версии должна быть позже предыдущей подтверждённой. |
| `profile_version_conflict` | Версия с такой датой уже существует. |
| `forbidden` | Недостаточно прав. Изменять профиль могут владелец и бухгалтер. |
| `email_not_verified` | Подтвердите электронную почту, чтобы сохранять профиль. |
| `csrf` | Сессия устарела. Обновите страницу и войдите снова. |
| `idempotency_conflict` | Повторите действие с новым ключом запроса. |
| `not_found` | Организация или версия профиля не найдена. |

### 4.2 field_errors / валидация snapshot

| Код | Текст |
| --- | --- |
| `invalid_value` | Выберите значение из списка. |
| `special_rates_requires_usn` | Спец. ставки НДС 5/7% применимы только при УСН. |
| `regime_requires_ip` | Выбранный режим налогообложения доступен только для ИП. |
| `ooo_incompatible_with_ip_regime` | Для ООО этот режим недоступен. |
| `with_deductions_requires_vat_payer` | Вычеты по НДС указывают только плательщики НДС. |
| `special_without_requires_special_rates` | Режим без вычетов — только при спец. ставках 5/7%. |
| `only_for_exemption` | Признак ст. 145 — только при статусе «освобождение». |
| `incompatible_with_deductions` | Освобождение по ст. 145 несовместимо с вычетами по НДС. |
| `only_for_vat_payer` | Ставка НДС по умолчанию — только для плательщика НДС. |
| `invalid_rate` | Недопустимая ставка НДС. |
| `only_for_usn` | Объект УСН заполняется только при системе УСН. |
| `must_be_empty_for_new_org` | Для новой организации диапазон выручки прошлого года не указывают. |
| `_confirm_minimum` (список полей) | Подписи по имени поля: «Укажите …» (маппинг полей → русские названия шагов). |

## 5. Состояния интерфейса

| Состояние | UI |
| --- | --- |
| **Загрузка** | Скелет в `Shell`; disable кнопок шага. |
| **Ошибка сети** | Banner danger + «Повторить» (refetch). |
| **409** `already_confirmed` / `idempotency_conflict` | Явное сообщение; для confirm — перечитать версии. |
| **403** | EmptyState или Banner: права / почта. |
| **404** профиля | Редкий bootstrap: «Профиль создаётся» + retry (или редирект в support). |
| **Пустая организация** | Нет компании в tenant — `CompanyWritePicker` как на других экранах. |
| **Viewer** | Все поля read-only; ссылка «Обратитесь к владельцу или бухгалтеру». |

## 6. После подтверждения

На `/settings/org-profile` (режим **карточка**):

- Краткая **карточка**: форма, режим, НДС, источник, каналы (русские подписи).
- **Статус**: подтверждено, роль `confirmed_role`, дата.
- **Кнопка** «Изменить режим с даты…» → модалка: месяц `effective_from`, `change_reason` → POST version → мастер.
- **История версий**: таблица из GET versions (`effective_from`, `is_confirmed`, `confirmed_at`, ссылка «Просмотр» read-only).

Обзор: баннер неподтверждённого **снимается** только когда на текущий период `is_confirmed: true`.

## 7. Предпросмотр FA-R03.2 (статический блок)

На шаге 6 (и в карточке): секция «Рекомендуемые выгрузки» — **без** загрузки файлов, P5, статусов «получено».

Алгоритм отображения (клиент, по snapshot):

1. **Базовый набор** (всегда при `bank` в `money_channels`): выписка ClientBank, карточка 51, ОСВ — тексты из [FA-R03.2](FA-R03.2-export-checklist-by-profile.md).
2. **+ эквайринг** если channel `acquiring`.
3. **+ касса** если `cash`.
4. **+ дебиторка** если `onec` или `cloud` и сфера торговля/услуги/смешанная.
5. **+ НДС** если `vat_status` ∈ {плательщик, спец. ставки}.
6. **+ производство** — счета 20/25/26 при `production` / `mixed`.
7. **+ расходы УСН** при `usn_tax_object` = доходы минус расходы.

Только названия отчётов и период «месяц»; без внутренних кодов импорта.

## 8. Доступность и тексты

- Язык интерфейса: **русский**, без англ. кодов в теле экрана (коды — в dev-only или tooltip «техническая информация»).
- `change_reason`: max **500**, счётчик символов, placeholder «Кратко, без персональных данных».
- Кнопки с `min-h-tap`; фокус на ошибках полей.
- Баннеры: `role="alert"` для danger, иначе `status` (как `Banner.tsx`).

| 6 | Автозаполнение `effective_from` при смене режима | **Первое число следующего месяца** по TZ компании (default). |
| 7 | Блокировать ли confirm при `support_level=unsupported`? | **Нет** (ADR: не блокирует подтверждение) — баннер + явный текст риска. |
| 8 | E2e на staging synthetic «Топ» vs отдельная тестовая org | **Отдельная** org в tenant владельца; не смешивать с пилотными выгрузками (FA-R03.1). |
